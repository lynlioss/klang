# Plugins and lyrics

Klang ships its first functional plugin: **LRCLIB**, with type `lyrics`. Enable it in Settings → Plugins, then tap Lyrics in Now playing. Tap the plugin row to read its overview, open its homepage, donate, or adjust its settings. Both external buttons open https://lrclib.net/.

## Adding a provider

Bundled JSON manifests live in `app/src/main/assets/plugins`. Each manifest declares a stable `id`, `type`, name/version/author, summary, description, features, privacy description, external `buttons`, and typed `settings`. Buttons declare a label, HTTPS URL, and icon (`website` or `donate`). Settings support `boolean` and integer `range` values, with defaults and range bounds/steps. `PluginsScreen` renders these declarations generically. Enabled IDs and per-plugin settings persist in `klang_plugins` preferences; plugins start disabled.

Implement `LyricsProvider` with the same ID and register the implementation in `PluginRegistry.lyricsProviders`. `find` accepts song metadata and returns a `LyricsDocument` or null when no match exists. A document supports plain text, instrumental status, timed lines, and optional words with absolute start/end times in milliseconds. Provider failures are caught at the repository boundary; the next enabled provider is tried in registry order. Provider IDs accompany returned lyrics for attribution and settings. This is a bundled capability API, not a system for downloading executable code.

## LRCLIB behavior

Requests happen when the lyrics view opens, changes track, or retries; enabling the plugin does not scan or upload the library. The client identifies Klang, sends sequential HTTPS requests, spaces them apart, and honors rate-limit/service `Retry-After` cooldowns. `/api/get` uses title, artist, album and duration. A missing exact match falls back to `/api/search`. A usable line-only or plain match also searches for a timing upgrade when the local duration is known. Candidates require matching title/artist and duration within two seconds. Parsed word timing wins over line/plain timing, followed by matching album and the closest duration; a line-only duplicate cannot hide a valid word-synced recording. Search failures preserve usable exact lyrics, and instrumental matches return directly.

The parser reads LRCLIB's Lyricsfile YAML using a safe constructor with size, nesting and alias limits. It supports word/line timings and overlapping vocals, then falls back to standard or enhanced LRC. Songs with word timestamps use word sync; a line without words highlights as a whole at its supplied line timestamp. Word timestamps are never estimated from line durations. Plain lyrics remain scrollable without fabricated synchronization. Timing adjustment shifts display and line-tap seeking together. LRC's embedded offset follows its convention: positive values advance lyrics. Fallback matches require duration within two seconds, matching LRCLIB's documented tolerance.

Release shrinking preserves SnakeYAML package names. Its logger initialization uses `Class.getPackage().getName()`; Android returns null for classes moved into the default package. `scripts/verify-release-lyrics.py` runs the actual APK's obfuscated parser in Android Runtime and checks Homecoming's supplied word boundaries and line-only behavior. This check does not install or open the app.

Successful provider documents are cached privately for repeat/offline listening, bounded by count and disk size. Cached documents from the previous lookup policy are refreshed when opened, and current documents refresh after one day to pick up newly published timing. A failed refresh preserves offline lyrics, and a refresh never downgrades existing word timing. Disabling offline storage deletes that provider's cache. Disabling a provider excludes it from lookup and closes lyrics when no lyrics provider remains enabled. In-flight results are cancelled when the track, configuration or view changes. The UI reads Media3's actual playback position to follow seeks, pauses and buffering; it does not run a separate advancing clock.

## Design and validation

From M3: paired container/on-color roles, native switches/sliders/buttons, emphasized type hierarchy and expressive spatial/effects springs. Klang design decisions: a simple plugin list retaining Spotify and YouTube Music rows, the official LRCLIB site icon, cover-colored lyrics, large lyric rows, a reading anchor near the upper third, softly blurred distant lines and edge fades. Word fill travels left to right with a feathered leading edge and bloom. Each completed word has a small lift and spring settlement; line transitions use spring scale/lift with an entry bloom. The fill follows the actual playback clock, including backward seeking, without delaying timestamps to animate opacity. Completion pulses skip opening past words and large clock jumps. Motion respects the system animator setting.

Top and bottom lyrics controls fade and gently move out after three seconds without touch. Their space stays reserved so the lyrics reading position never jumps. Touch restores them; the revealing gesture is consumed to avoid accidental line seeking or playback changes. Touching or scrubbing holds the controls open and restarts the timeout on release. Touch exploration keeps them visible. Manual scrolling pauses auto-follow and exposes a Follow lyrics control while the controls are visible.

Text layout and word geometry are published together from `onTextLayout` as one `LyricTextLayout` snapshot. Drawing waits for that complete snapshot, including each word's wrapped bounds and transform pivot. Computing geometry during composition instead left a first-frame race: layout became visible after measurement while the drawing closure still held empty pivots. Whitespace and invisible word fragments retain safe empty geometry and are skipped when drawing.

Parser, manifest, provider, cache and interaction tests cover supplied word timing, line-only synchronization, YAML safety/fallback, LRC timestamps, backward seeks, instrumental gaps, plain lyrics, duplicate selection, duration/title/artist matching, metadata, rate-limit error handling, cache refresh/offline fallback, cancellation, the inactivity timeout, touches and word completion crossings. Geometry checks cover initial word bounds/pivots, wrapped words, whitespace/invisible fragments and remeasurement. A small Homecoming fixture preserves the shape and timings of LRCLIB record 1032055. On-device interaction and TalkBack review remain manual checks.
